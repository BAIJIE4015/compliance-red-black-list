# 企业合规红黑榜 · 合规观察索引

面向全球企业的合规观察索引：记录**开源与软件合规、破解与非法盈利、独立设计与跟风设计、作息与用工合规**四大场景的公开信息与待核验线索，服务于合规预警与风险参考，而非单纯曝光。

**核心理念：可核验 · 可申诉 · 可撤销。**

> **演示数据声明**：当前站点全部榜单条目、名称、行业与证据均为**虚构演示内容**，仅用于验证版式与视觉系统效果，**不针对任何真实存在的企业、组织、个人或开源项目**，不构成事实指控、合规评价或法律结论。真实收录以公开司法判决、行政处罚、监管通报或可靠第三方报告为准。

## 功能

- **四大场景分区**：每个场景独立页面，内部按四级榜单展示
- **四级榜单**：红榜（合规可推荐）/ 观察名单（风险提示不下结论）/ 灰名单（未证实，可申诉）/ 黑名单（有处罚/判决/通报依据）
- **企业速查**（首页）：按企业名称搜索，聚合展示同一主体在各场景分别落在哪一级榜单（跨榜单归属一目了然）
- **子项查询过滤**：每个榜单表格独立关键词过滤，实时匹配计数
- **状态机闭环**：`gray_unverified`（待考证）→ `gray_self_proof`（待自证）→ `blacklisted` / `red`，含 `revoked`（撤销）与 `appealing`（申诉中）分支
- **审核与申诉通道**：黑/灰名单准入条件、申诉流程、反证材料与防滥用规则

## 数据与内容规范

- **表格为唯一数据源**：榜单条目以各场景页表格为准；`assets/js/search-data.js` 为速查索引，修改条目后需按该文件头部说明重新生成。
- **演示数据三重标记**：任何演示条目必须同时满足 ①页面顶部 `.demo-banner` 声明 ②名称含「演示主体 / 虚构」③名称后附 `.badge-demo` 徽标；证据列一律以【虚构】开头。真实数据上线时三层标记全部撤除。
- **内容红线**：演示样例禁止使用真实企业/组织/个人/开源项目名称；不呈现破解细节；「跟风」不等于违法，独立设计与跟风设计需按证据分档；无来源的指标、认证、排名不得出现。

## 设计系统

视觉系统以 [`DESIGN.md`](DESIGN.md) 为唯一口径：语义颜色令牌（四级榜单颜色 + 文字双编码）、字阶角色、4px 间距刻度、两级圆角、交互状态全集（default/hover/focus-visible/active/disabled/loading/empty/error）。样式按 tokens → base → layout → components → utilities 五层组织，新增样式先进令牌层再引用，禁止一次性颜色/间距/内联样式。

## 参与

欢迎以四种方式参与，详见 [CONTRIBUTING.md](CONTRIBUTING.md)：

1. **提交线索** —— 附公开可核验证据的合规线索
2. **申诉与反证** —— 被收录主体提交反证材料，核验后可降级、撤销或转观察名单
3. **内容纠错** —— 指出事实错误、过期信息或分档不当
4. **代码与设计贡献** —— 页面、组件、可访问性与视觉系统改进
