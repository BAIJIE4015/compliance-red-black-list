开源与软件合规

场景一 · 记录开源许可证使用、商用授权与 GPL / AGPL / SSPL / BSL 等传染性许可证的合规风险，评价维度覆盖许可证选型、隔离要求、更新与 Release 核查

场景概述

本场景的收录范围、评价维度与观察口径

本场景记录企业在开源软件引入、使用与分发中的合规表现：许可证使用是否合规、商用授权是否完备、GPL / AGPL / SSPL / BSL 等传染性或 source-available 许可的义务是否被正确履行。商用闭源产品优先选用 MIT、BSD、Apache-2.0；GPL / AGPL 需隔离，网络服务尤其注意 AGPL 可能触发的源码开放义务；SSPL / BSL / POCL 等 source-available 许可并非传统开源许可，须逐条阅读限制条款。

评价口径：筛选与核查不只看 GitHub Star，还须核查近 6 个月更新频率、是否有正式 Release、许可证是否发生变更；结论随证据与版本动态更新，可申诉、可撤销。

判定要点

本场景的准入标准、评价维度与风险提示

  • 许可证选型：商用闭源产品优先 MIT / BSD / Apache-2.0；GPL / AGPL 组件须与闭源部分隔离，网络服务场景重点关注 AGPL 的源码提供义务。
  • source-available 许可：SSPL / BSL / POCL 等并非传统开源许可，接入前逐条阅读限制条款，评估对商用分发与托管服务的影响。
  • 动态核查维度：核查近 6 个月更新、是否有正式 Release、许可证是否变更，不只依赖热度指标；红榜结论随版本与证据动态复核。
